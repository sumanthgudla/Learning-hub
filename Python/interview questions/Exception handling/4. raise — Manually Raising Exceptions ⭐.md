# 4. `raise` — Manually Raising Exceptions ⭐

So far, we've seen Python **automatically raise** exceptions:

```python
result = 10 / 0
```

Python raises:

```text
ZeroDivisionError
```

But sometimes **we want to raise an exception ourselves**.

That's where `raise` comes in.

---

## 1. Basic `raise`

```python
age = -5

if age < 0:
    raise ValueError("Age cannot be negative")
```

Output:

```text
ValueError: Age cannot be negative
```

We're telling Python:

> "This situation is invalid, so raise an exception."

---

## 2. Why use `raise`?

Imagine a function:

```python
def withdraw(amount):
    if amount < 0:
        raise ValueError("Amount cannot be negative")

    print("Withdrawing", amount)
```

Now:

```python
withdraw(-100)
```

Instead of allowing invalid data to continue through your application, we stop it immediately.

This is called **input/business-rule validation**.

---

# 3. `raise` with `try/except`

You can raise an exception and then catch it.

```python
try:
    age = -5

    if age < 0:
        raise ValueError("Age cannot be negative")

except ValueError as e:
    print("Error:", e)
```

Output:

```text
Error: Age cannot be negative
```

Here:

```python
raise ValueError("Age cannot be negative")
```

creates/raises the exception.

And:

```python
except ValueError as e:
```

catches it.

---

# 4. What is `as e`?

You've probably seen:

```python
except ValueError as e:
```

`e` contains the **exception object**.

Example:

```python
try:
    raise ValueError("Invalid age")

except ValueError as e:
    print(e)
```

Output:

```text
Invalid age
```

You can think of:

```python
as e
```

as:

> "Give me the exception object so I can inspect it."

---

# 5. `raise` without an exception

This is a **very important concept**.

Inside an `except` block, you can write:

```python
raise
```

Example:

```python
try:
    x = 10 / 0

except ZeroDivisionError:
    print("Logging the error")
    raise
```

Output:

```text
Logging the error
ZeroDivisionError: division by zero
```

What's happening?

```text
Exception occurs
      ↓
except catches it
      ↓
Log / process it
      ↓
raise
      ↓
Exception is raised again
```

This is called **re-raising an exception**.

---

# 6. Why re-raise?

This is common in production applications.

For example:

```python
try:
    process_payment()

except Exception as e:
    log_error(e)
    raise
```

We want to:

1. Log the error
2. But **not hide the error**
3. Let the higher-level application handle it

Without `raise`:

```python
except Exception as e:
    log_error(e)
```

the exception might be swallowed, and the application could incorrectly think everything succeeded.

---

# 7. `raise` vs `raise Exception(...)`

These are different:

### Create a new exception

```python
raise ValueError("Invalid input")
```

You're saying:

> "Raise this new `ValueError`."

### Re-raise the current exception

```python
raise
```

You're saying:

> "Raise the exception that I'm currently handling again."

---

# 8. Interview question ⭐

### What is the difference between `raise` and `raise e`?

You may see:

```python
except Exception as e:
    raise
```

versus:

```python
except Exception as e:
    raise e
```

Both raise an exception, but **plain `raise` is preferred for re-raising** because it preserves the original traceback more cleanly.

For interviews, remember:

```text
raise Exception(...) → raise a new exception

raise                → re-raise the current exception
```
